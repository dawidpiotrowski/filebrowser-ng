# Atomic file mutations, local implementation, 2026-10-21

This work follows local commit `70dc83a1` and implements the next file-integrity slice from the [security plan](roadmap.md). **It is local, unreleased source: no push, tag, image publication, release or deployment.** The public NAS is unchanged.

Local implementation commits: `e74dd963` (filesystem/HTTP/TUS primitives and regressions) and `ed49c94b` (conditional editor saves and frontend regressions).

## Reproduced failures

Before integrating the new mutation paths, deterministic HTTP regressions reproduced:

- `rename` returning 200, deleting the source name and replacing a destination created after the conflict check. This also happens with automatic suffix selection and with both `override=true&rename=true`.
- Editor PUT and ordinary overwrite POST returning an error after a broken request body, with the original file replaced by the partial string `partial`.
- TUS overwrite exposing `he` in place of the old file after only the first two bytes of a five-byte upload.

The new regressions preserve both files in a rename conflict, preserve the original on failed writes, and keep the original readable throughout an incomplete TUS overwrite. This addresses the open rename/overwrite concerns in the [earlier local review](follow-up-review-2026-10-21.md); that report describes its earlier starting state.

The native exclusion semantics come from the [Linux rename API](https://man7.org/linux/man-pages/man2/rename.2.html), [Apple rename implementation](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/vfs/vfs_syscalls.c) and [Microsoft rename information contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information). Descriptor-relative operations keep traversal checks anchored instead of reconstructing unrestricted absolute paths.

macOS ACL preservation uses bounded descriptor-based extended-security attributes, following Apple's [attribute packing contract](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/man/man2/setattrlist.2) and [ACL handling](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/vfs/vfs_attrlist.c). Linux preserves its POSIX ACL xattr and removes an inherited staged access ACL when the original has none. Filesystem/permission errors are returned; there is no truncating fallback.

## Limits and operational behavior

- **Atomic visibility is per file.** Readers see an old or complete new inode. Recursive directory copies may have completed children when another child fails. Cross-volume directory moves return 501 with the source retained; use a deliberate copy/verify/delete workflow instead.
- **One writer process per tree remains required.** The process lock coordinates application commits, rename and remove; it does not turn overwrites or source deletion into a kernel compare-and-swap against arbitrary host writers. Host writers able to rename private staging entries or move an opened tree outside its scope remain outside the application boundary. Metadata-based ETags are not content hashes or a guarantee against external writers deliberately preserving identity/timestamps. Native Windows validation must include creation-time identity on filesystems with coarse timestamps.
- **The commit point matters.** A request can complete publication but lose its response. A directory-sync error after rename reports that publication already happened; it cannot restore the old inode. File flush/close failures before rename preserve the old target. Unix directory fsync is used; Windows lacks the same directory-sync contract, and complete power-loss durability still depends on the filesystem, mount, storage hardware and NAS configuration.
- **New inode semantics are intentional.** Existing hardlink aliases and already-open readers retain the old inode after replacement. Filesystem directory write/delete rights and sufficient temporary space are required, in addition to write permission on the original. Security metadata that cannot be preserved causes failure rather than weaker permissions. Special filesystem flags, every network-filesystem behavior and native Windows runtime behavior need further validation.
- **Staging has a bounded active count, not a disk quota.** At most 256 staged writes/TUS jobs are active per process; additional work gets 429. TUS retains the existing three-minute idle timeout, now discarding private partial data on expiry. No resumability survives restart. After a crash, orphan directories remain reserved and inaccessible through the app; inspect/recover their payloads outside the served tree during maintenance before removing them. Startup does not blindly delete matching host paths.
- **Unsupported capabilities fail closed.** Unknown filesystem adapters and unsupported native exclusion operations return an error, normally 501. There is no unsafe stat/rename or direct-truncation fallback. Case-only renames on case-insensitive filesystems follow native exclusion behavior and may return a conflict.

See [migration notes](../migration.md#atomic-file-mutations-local-unreleased) for API/container compatibility. No database schema, port, UID/GID or image tag is changed here.

## Validation

Validation uses disposable local data, including failure injection, concurrent commits and a separate native Linux filesystem for cross-volume movement. Results and commands are recorded under ignored `.local/atomic-writes-2026-10-21/`. Native Windows/NAS behavior and a power-loss test are future publication gates; cross-compilation alone does not establish them.

- macOS arm64: Go vet and complete race suite, **336 passing tests/subtests**, no skipped tests. Ownership/xattr/macOS ACL, read-only modes, failure injection, conditional editing and private-stage access checks pass.
- Linux arm64: complete Go suite with Go 1.27.3, **336 passing tests/subtests** and one intentional read-only-mode skip because the toolchain container runs as root. The Linux POSIX ACL and real cross-volume move tests pass. This disposable container runs tests with no network and a read-only source/module mount; it does not deploy the application.
- Windows amd64: files, fileutils and HTTP test binaries cross-compile. Native execution has not been performed.
- Frontend: formatting, lint, **46 tests**, typecheck and production build pass. The server builds after the frontend.
- `govulncheck@v1.9.0`: zero reachable vulnerabilities and zero vulnerable imported packages; one advisory remains in an unused required module. The pnpm audit gate passes with the existing braces advisory exception backed by its patch/tests. Dependency versions and exceptions are unchanged; x/sys is now classified as a direct dependency.
