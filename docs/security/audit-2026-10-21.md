# Security audit — 2026-10-21

## Scope and baseline

Initial maintenance and security review of filebrowser-ng, forked from `filebrowser/filebrowser` commit `833d908884d5c801f30f5c098d7977177eb3a36b` (final upstream release v2.63.23). The Git history and Apache-2.0 license are retained; the Go module is now `github.com/dawidpiotrowski/filebrowser-ng/v2`.

Reviewed authentication, JWT/session lifecycle, signup/proxy provisioning, filesystem confinement, authorization rules, resource mutations, TUS/cache eviction, shares, raw/archive downloads, subtitle/text reads, static branding, preview configuration, dependencies, and CI/distribution settings. Evidence includes the published upstream advisories, manual code review, regression tests, dependency analysis, static analysis, and local application/container smoke tests.

This is an initial audit of the listed surfaces, not a proof of the absence of vulnerabilities. It does not include third-party penetration testing, exhaustive fuzzing, every frontend feature, hostile mount namespaces, or a production migration.

## Additional findings and fixes

| Finding | Impact | Change and evidence |
| --- | --- | --- |
| Nonexclusive file create after stat | Create-only upload can truncate a file appearing concurrently | Bind creation to `O_EXCL`; modify-only PUT cannot create a vanished target; exclusive-create regression |
| Share creation overlaps API delete/rename | A just-created link can survive invalidation | Serialize share creation with invalidating filesystem mutations in the single writer process |

| Concurrent symlink replacement between scope check and OS operation | Escape through a check/use race | Use `os.Root` for OS filesystem operations and reject special files after non-blocking open; retain abstract afero behavior for non-OS filesystems |
| Cyclic directory aliases in archive walk | Unbounded recursion/resource use | Track resolved visited directories and cap tree depth/entry count; Unix archive regression |
| Slice mutation while filtering expired shares | Panic or incorrect filtering of consecutive expired links | Build a separate result slice; consecutive-expiry regression |
| Deferred upload expiry cleanup deletes a replaced path | Unrelated replacement data can be removed | Expiry removes only cache state and retains partial files; replacement regression |
| Text file grows after metadata check | Unbounded preview allocation | Cap actual read, independent of stat size; encoded download streams |

## Session and share behavior

JWTs carry a random session ID; the server requires a matching, non-expired persisted session and current credential fingerprint. Logout deletes the session. Renewal deletes the old session and creates its replacement in one Bolt transaction, so the same token cannot renew twice. Password changes through HTTP, CLI, or a restarted process change the fingerprint and invalidate existing sessions. Session persistence and revocation are tested across a database reopen. Legacy JWTs without session records fail closed.

Proxy authentication checks the TCP peer against explicitly configured CIDRs and requires the same asserted identity on authenticated API requests. It never treats `X-Forwarded-For` as evidence of trust. JWT expiry is always enforced. Correct identity-header stripping remains the proxy's responsibility.

Permanent password-share URL tokens are ignored. Successful password verification creates an HttpOnly, SameSite=Strict grant cookie, scoped to public endpoints and cryptographically bound to one share/password credential, with a maximum lifetime of 15 minutes or the share expiry. Grants cannot authenticate regular user APIs. Cookies are Secure when served over TLS or when a TLS-terminating proxy correctly supplies `X-Forwarded-Proto: https`.

## Remaining boundaries and operational work

- External symlink following is an explicit legacy escape hatch; keep it disabled for untrusted trees. Hard links, bind mounts, devices accessible on the host, and malicious host administrators are outside pathname confinement. `os.Root` is used for I/O/removal/rename; metadata-time updates inherit the platform's `os.Root.Chtimes` caveats. Rules are not a snapshot against concurrent host changes within a scope.
- Use one writer process per filesystem tree. Redis coordination is rejected until filesystem fencing exists. Mutations from external processes can still race application operations; expiry cleanup intentionally retains incomplete files. File creation permissions do not provide storage quotas.
- A share of a directory intentionally exposes its changing contents. External deletion/recreation or direct database manipulation bypasses API revocation; review historical shares during migration. Short-lived password grants remain bearer credentials until expiry, and there is no separate share-grant logout endpoint.
- Browser JWTs remain in localStorage for compatibility, so XSS prevention remains essential. HttpOnly cookies protect cookie-based reads, not JavaScript-accessible API tokens. Concurrent renewal is serialized within a browser tab; custom API clients and multiple tabs must handle consumed tokens by logging in again.
- Large legitimate images, directories, archives, or many parallel downloads can still consume resources. Use container limits, filesystem quotas, reverse-proxy limits, and least-privilege mounts. Password rate budgets use the peer address; users behind one proxy share its budget.
- No public release was tagged and no production service was upgraded by this task. The new runtime container is built locally from source. Review migration settings and test real browser/media workflows before deployment.
